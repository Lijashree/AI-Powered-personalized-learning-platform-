A. PROJECT OVERVIEW
================================================================================
StudyMind AI is an intelligent full-stack personalized learning platform designed
for students preparing for university exams and campus placements. It combines
modern web development, vector embeddings, student-specific Retrieval-Augmented
Generation (RAG), and code execution into a single, cohesive application.

1. Architecture Overview:
   - Frontend:
     * Built with React 18, React Router v6, Tailwind CSS, Monaco Editor, Sonner.
     * Running on: http://localhost:3000
     * Handles student authentication state (JWT stored in localStorage), dark/light
       mode, interactive study dashboards, Monaco code editor, and unified history.
   - Backend:
     * Built with FastAPI (Python 3.9+ / 3.11+ async framework), Uvicorn ASGI server.
     * Running on: http://localhost:8000
     * Swagger Interactive API Documentation: http://localhost:8000/docs
     * Exposes RESTful endpoints for Auth, Notes, Quizzes, Flashcards, Roadmaps,
       Interview Preparation, Coding Execution, Doubt Solving (RAG), and Analytics.
   - Database:
     * MongoDB (Local MongoDB Server on localhost:27017 or MongoDB Atlas in the cloud).
     * Database Name: studymind_db
     * Collections: users, questions, notes, quizzes, flashcards, roadmaps,
       module_details, coding_challenges, interviews, doubt_chats, goals, saved_codes.
   - AI & Machine Learning:
     * LLM Engine: OpenRouter API (google/gemini-2.5-flash) for generative tasks.
     * Embeddings: Sentence-Transformers (all-MiniLM-L6-v2) for semantic question
       similarity and topic categorization.
     * Personal RAG: Cosine similarity search over the authenticated student's own
       learning history to provide contextual doubt resolution and prevent re-study.
     * Code Sandbox: Local subprocess runner for Python and Java with strict 5s timeouts.

L. TROUBLESHOOTING GUIDE
================================================================================

1. Error: "Email already registered" on signup
   Cause: An account with this email already exists in MongoDB.
   Fix: Sign in via http://localhost:3000/login or use a different email.

2. Error: "pymongo.errors.ConfigurationError: The DNS query name does not exist"
   Cause: The MONGO_URL in backend\.env points to a deleted, paused, or mistyped
          MongoDB Atlas cluster domain (e.g. cluster0.qlks4tb.mongodb.net).
   Fix: Our resilient database manager in app/database.py automatically falls back
        to local MongoDB (mongodb://localhost:27017). If you wish to use Atlas,
        create a fresh cluster in cloud.mongodb.com and paste the new connection
        string into backend\.env.

3. Error: "Server connection failed" or "Network Error" on frontend
   Cause: The backend server is not running on port 8000.
   Fix: Open Terminal 1, navigate to backend\, and run: python server.py.
        Confirm by visiting http://localhost:8000/api/health.

4. Error: "OpenRouter API Key is not configured"
   Cause: OPENROUTER_API_KEY is missing from backend\.env.
   Fix: Open backend\.env and ensure OPENROUTER_API_KEY=YOUR_OPENROUTER_API_KEY_HERE is present.
        Restart the backend server.

5. Error: "This request requires more credits, or fewer max_tokens" (HTTP 402)
   Cause: OpenRouter account has insufficient credits for the requested model.
   Fix: Visit https://openrouter.ai/settings/credits to add credits or adjust
        AI_MODEL in backend\.env to a free tier model (e.g., meta-llama/llama-3.2-3b-instruct:free).

6. Java Code Execution Error: "javac is not recognized"
   Cause: Java JDK is not installed or not in system PATH.
   Fix: Install OpenJDK (version 17 or 21) and add its bin folder to PATH.
        Python code execution will continue to function normally regardless.

7. Port 8000 Conflict:
   Cause: Another application or older python process is using port 8000.
   Fix in PowerShell:
   Get-Process -Id (Get-NetTCPConnection -LocalPort 8000).OwningProcess | Stop-Process -Force
